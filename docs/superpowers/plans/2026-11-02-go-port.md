# extract Go Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Perl `bin/extract` with a Go binary. It reads the same config, runs the same hooks with the same arguments, and builds the same rsync commands, but fails loudly and stays silent when healthy.

**Architecture:** There are three layers, plus a shared helper:
- **Startup:** `cmd/extract` parses flags (kong), then loads and validates the config (`internal/config`) and resolves the host list (`internal/extract`).
- **Run:** a pure runner (`internal/extract.Run`) executes hooks and rsync through a process-group-aware exec helper (`internal/proc`). It returns a `Result` value and never prints.
- **Reporting:** `internal/report` turns the `Result` into slog output at the requested verbosity, plus an exit code.

**Tech Stack:** Go 1.27, `github.com/alecthomas/kong`, `github.com/gavincarr/kong-help-colours`, `github.com/joho/godotenv`, `golang.org/x/sys/unix`, stdlib `log/slog` and `testing`.

**Spec:** `docs/superpowers/specs/2026-11-02-go-port-design.md`. Read it before starting any task. Where this plan and the spec disagree, the spec wins; flag the conflict.

## Global Constraints

**Module and dependencies**
- Module path `github.com/gavincarr/extract`. Use the `go` directive written by `go mod init` (Go 1.27 toolchain).
- Dependencies: only the four libraries above plus the stdlib. Tests use stdlib `testing` only (no testify).
- Logging: everything goes through `log/slog`. Never import stdlib `log`, and don't call `slog.SetDefault`.
- Linux only. Process-group handling uses `syscall.SysProcAttr{Setpgid: true}` and `kill(-pgid)`.

**CLI**
- Every kong field has an explicit `name:` tag.
- Verbosity is `Verbose int` with `type:"counter"`, never `[]bool` (it hangs).
- On a usage error, usage is written to stderr, and kong's exit code 80 maps to 2. `--help` exits 0.
- Exit codes: `0` everything OK; `1` the run happened but a host failed or timed out, or a hook failed; `2` usage or config error, nothing extracted.

**Defaults and fixed values**
- Defaults: config `/etc/extract/extract.conf`; `-t` 60 (seconds); `EXTRACT_SCRIPTS_DIR` `/etc/extract/scripts`; `EXTRACT_HOOK_TIMEOUT` 600 (seconds). A timeout of `0` means none.
- rsync argv order is pinned: `rsync --archive --copy-links --delete --rsh=ssh -o BatchMode=yes` (the `--rsh=` value is a single argv element), then `--quiet` or `--verbose`, then `[--dry-run]`, then `[--files-from=…]`, then `<src> <dest>`.

**Process**
- Leave the Perl (`bin/extract`, `lib/`, `t/`) untouched until Task 11.
- Commits follow Conventional Commits and end with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never `git push`.

## Review Focus

These five inputs or conditions are not exercised by the spec's own test list. Each line names the task that adds a test for it.

1. **rsync missing from `PATH`** (e.g. a fresh box, or cron's minimal PATH). Expect exit 2 with "rsync not found" before anything runs, not N per-host failures. *Test: Task 8.*
2. **A hook that backgrounds a child holding stdout open** (`pre_extract_load_ssh_keys` starts `ssh-agent`). Expect the hook's exit to be seen promptly, not a hang until the hook timeout. *Test: Task 2.*
3. **Relative paths** (`-c conf/extract.conf`, `EXTRACT_ROOT=data`). Expect hooks to receive absolute `$1`/`$2`, because they `cd` before sourcing the config. *Test: Task 3.*
4. **Malformed hosts from any source**, including `EXTRACT_HOST_CMD` output (`u@`, `@h`, `-h`, `a/b`, CRLF line endings). Expect exit 2 naming the bad host, never an rsync with an odd argument. *Test: Task 4.*
5. **Config lines bash accepts but a naive parser might not**: `export KEY=…`, inline `# comments`, single quotes, CRLF. Expect the same values bash would see. *Test: Task 3.*

- [ ] **Step 3: Implement `Run` in `proc.go`**

- Use `exec.Command` with `SysProcAttr{Setpgid: true}`. Leave `Stdin` nil (that gives `/dev/null`). Use separate `bytes.Buffer`s for stdout and stderr, and set `WaitDelay = pipeWaitDelay`.

### Task 7: Reporter, slog handler, exit code

**Files:**
- Create: `internal/report/handler.go`, `internal/report/report.go`, `internal/report/report_test.go`

**Interfaces:**
- Consumes: `extract.Result`, `HostResult`, `HookResult`, `Status`, and `proc.StepResult`
- Produces:
  ```go
  const LevelTrace = slog.LevelDebug - 4
  // NewLogger: the level is Warn at v=0, Info at 1, Debug at 2, and LevelTrace at >=3.
  // Each record is written as its message plus "\n", with no time, level or attrs.
  // Records at Warn and above go to stderr; the rest go to stdout.
  func NewLogger(stdout, stderr io.Writer, verbosity int) *slog.Logger
  func Report(log *slog.Logger, r *extract.Result)
  func PrintPlan(w io.Writer, r *extract.Result)   // noop plan, regardless of verbosity
  func ExitCode(r *extract.Result) int             // 0 if r.OK(), else 1
  func shellJoin(argv []string) string             // single-quotes elements containing spaces or shell metacharacters
  ```

**Pinned output** (`<out>` means each line of the captured stream, indented by two spaces):
- **Error level, one per failed or timed-out host:** `<host>: <Error>`, followed by the failing step's stderr. For a hook failure, it's the hook's stdout then stderr.
- **Error level, setup/teardown hook failure:** `<stage> hook <path> exited <n>` (or `timed out after <d>`), then its output.
- **Error level, when aborted:** `run aborted: no hosts extracted`.
- **Info level, warnings:** `<host>: warning: <warning>`.
- **Info level, summary when healthy:** `<n> hosts ok` (`1 host ok` when n is 1).
- **Info level, summary otherwise:** `<ok> ok, <failed> failed, <timedout> timed out`.
- **Debug level:** `<host> ok (<duration rounded to 0.1s>)`.
- **Trace level, per step that ran:** `+ <shellJoin(argv)>`, then `<out>` for its stdout and stderr.
- **Plan lines:** `would run <stage>: <shellJoin(path+args)>` and `would rsync: <shellJoin(argv)>`, in execution order.
